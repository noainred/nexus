관리자 로그인

이 매니저는 비밀번호로 보호되어 있습니다.

토폴로지 (프록시 연결 구조)

각 프록시 저장소의 원격 주소로 노드 간 부모↔자식 관계를 도출합니다. 상위 노드가 다운된 끊긴 링크는 빨갛게 표시되며, 해당 프록시는 Auto-block 위험이 있습니다.

계위 상황판(트리 다이어그램)은 개요 탭에 있습니다. 아래는 노드별 프록시 링크 상세입니다.

프록시 원격 상태 보드 (Auto-block)

전 서버의 프록시 저장소가 각자 원격(remote)에 연결 가능한지, Remote Auto Blocked 상태인지를 한 표로 보여줍니다. 차단된 프록시는 해당 서버 Nexus가 원격에 못 닿고 있다는 뜻입니다.

계위 상황판

정상 노드 다운 노드 끊긴 링크 노드를 클릭하면 그 서버의 Nexus가 새 탭으로 열리고, 드래그하면 원하는 위치로 배치됩니다(자동 저장)

인스턴스 상태

통합 검색 (전 서버 아티팩트)

검색어로 모든 서버의 컴포넌트(아티팩트)를 한 번에 찾아, 어느 서버·저장소에 어떤 버전이 있는지 보여줍니다. 취약 라이브러리 추적·배포 확인에 유용합니다.

Blob Store 사용량

디스크 포화 예측

6시간마다 자동 수집한 사용량 추세로 각 blob store가 90%에 도달할 시점을 예측합니다. 빨강(7일 이내/90% 이상)·노랑(21일 이내/80% 이상)은 정리(Cleanup·Compact)나 증설이 필요합니다. 표본이 2개 이상 쌓여야 증가율이 계산됩니다.

JVM / 리소스

인프라 체크 (서버 Ping)

매니저에서 각 서버로의 TCP 연결 지연(ms)을 주기적으로 측정해 1년간 누적합니다. 평소(중앙값) 대비 +20% 노랑, +50% 빨강으로 표시됩니다.

정상 +20% 이상 +50% 이상 평소(중앙값)

저장소 구성 비교 (인스턴스 × 저장소)

일치 설정 상이(drift) 누락 조회 불가

셀에 마우스를 올리면 전체 설정을, 셀(또는 저장소 이름)을 클릭하면 항목별 상세 비교 팝업이 열립니다(팝업의 서버 이름을 클릭하면 그 서버의 admin 저장소 설정이 새 탭으로 열림). 열 머리글(서버명) 클릭은 그 서버의 Nexus를 엽니다. 셀을 같은 행의 다른 서버 칸으로 드래그하면 설정이 대상 서버로 복사(덮어쓰기·없으면 생성)됩니다.

다운로드 현황 (실제 사용 패키지·용량)

서버와 저장소를 선택한 뒤 [시작]을 눌러야 조회합니다. 저장소 '전체'는 모든 저장소 요약을, 특정 저장소는 상세 내역을 보여줍니다.

스케줄 작업 (Tasks)

인스턴스의 스케줄 작업 상태·마지막 실행 결과를 확인하고, 직접 실행/중지할 수 있습니다. (예: Compact blob store, Cleanup)

보안 점검 (사이트별)

익명 접근 허용·기본 admin 계정·관리자 권한 계정을 점검합니다. 빨간 항목은 보안 위험입니다.

콘텐츠 동기화 점검 (사이트 간 실제 아티팩트 비교)

선택한 저장소의 실제 컴포넌트가 사이트마다 동일하게 있는지 비교합니다. 일부 사이트에만 있는 컴포넌트는 누락으로 표시됩니다.

알림 (임계치)

노드 다운·Heap·디스크 임계치를 주기적으로 점검합니다. Webhook(Slack 호환)을 설정하면 발생/해제 시 푸시됩니다.

정리(Cleanup) 정책

플릿 정리 점검 (전 서버)

서버별 정리 위생 상태를 한 번에 점검합니다 — cleanup 정책 수, 정책이 없는 저장소, Compact blob store 작업 유무(없으면 soft-delete가 디스크를 계속 차지). 필요 시 Compact를 전 서버에서 일괄 실행하거나, 정책을 전 서버로 복사할 수 있습니다.

※ Docker는 2단계입니다: ① Docker 정리(GC)로 고아 레이어를 지운 뒤 ② Compact로 실제 디스크를 회수합니다. GC 완료 후 잠시 뒤 Compact를 실행하세요.

새 정책 만들기

※ 최소 한 개 이상의 기준(N일)을 입력해야 합니다.

일괄 적용 (저장소 설정 일괄 변경)

서버를 선택해 설정 읽기를 누르면 그 서버 모든 저장소의 설정값을 항목별로 묶어 보여줍니다. 새 값을 입력하고 적용하면 그 항목을 가진 모든 저장소에 한 번에 반영됩니다. (예: httpClient.autoBlock 일괄 끄기/켜기) 항목이 없는 저장소(예: hosted에 proxy 설정)는 자동으로 건너뜁니다.

Nexus 서버 설정

관리할 Nexus 서버를 추가·수정·삭제합니다. 각 서버를 모니터링/비교에 사용할지 선택할 수 있습니다.

서버 목록

※ 각 서버 행의 설정 ↓로 그 Nexus의 구성을 JSON으로 받고, 복구 ↑로 그 JSON을 대상 서버에 다시 만듭니다(저장소·blob·정책 등). 이미 있는 항목은 건너뜁니다. 프록시 저장소의 캐시 파일은 복구 대상이 아니며 업스트림에서 자동으로 다시 받아옵니다.

새 서버 추가

※ 수정 시 비밀번호를 비워두면 기존 비밀번호가 유지됩니다.

그룹 표시 순서

개요(인스턴스 상태)에서 그룹이 표시되는 순서입니다. ▲▼로 조정하면 바로 저장됩니다.

계위 상황판 단계 이름

개요 탭의 계위 상황판 왼쪽에 표시되는 단계(tier) 이름입니다. 최상위·중계·말단 노드에 붙는 안내 문구를 원하는 단어로 바꿀 수 있습니다. (이 브라우저에만 저장됩니다)

비교 기준 항목

비교 매트릭스에서 '설정 상이(drift)'를 판단할 때 사용할 항목을 선택합니다. 체크한 항목만 비교합니다.

Ping 모니터링 설정

인프라 체크 탭의 측정 주기와 색상 임계치(평소 중앙값 대비 %)입니다.

서버 설정 백업

관리 중인 모든 Nexus 서버의 구성(저장소·blob·정책·보안·작업 등)을 지정한 시각에 매일 자동 백업합니다. 서버가 소실되거나 데이터가 지워져도, 백업 JSON을 서버 행의 복구 ↑로 가져와 신속히 복구할 수 있습니다. (설정 구성만 백업 — 아티팩트/blob 실데이터는 제외)

DR 준비도 점검 (DB 백업)

구성은 위의 '서버 설정 백업'이 책임지지만, 실데이터 복구에는 각 Nexus 서버 자체의 'Admin - Export databases for backup' 작업이 필요합니다. 모든 서버에 그 작업이 있고 최근 성공했는지 점검합니다. (작업 생성은 REST 미지원 — 없는 서버는 Nexus UI에서 만들어야 합니다)

예약 콘텐츠 동기화 (프록시 캐시)

원본 서버의 저장소 캐시를 대상(프록시) 서버에 매일 지정 시각에 자동으로 채웁니다. Pro의 콘텐츠 복제를 대신해, 마스터→사이트로 아티팩트를 미리 내려두어 원격 사이트의 첫 다운로드 지연을 없앱니다.
